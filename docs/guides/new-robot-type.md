# 接入一种新机器人

给要把一种新机器人（比如 Tron2）接进 xpisode 的同事。

## xpisode 帮你做什么

xpisode 管"录数据"这条路：
1. 实时读取机器人和相机的数据，录成文件；
2. 在网页面板上判断每条录制：要、失败、还是重录；
3. 把要的数据建成数据集，上传到团队共用的 OSS；
4. 训练和评测都从 OSS 读数据。

**你不用改 xpisode 本身。** 你要做的是三件事：
1. 写一个适配器，让 xpisode 能读写你的机器人；
2. 在本仓库里给你的机器人建一个目录；
3. 写一份"本体约定"，说明你的机器人有哪些数据流、各叫什么名字、用什么单位、动作是什么意思。

## 按这个顺序做

### 1. 先看懂 xpisode（不需要机器人）

照 xpisode 仓库的 `docs/tutorials/first-recording.md`，在自己的电脑上录一条演示数据，看看录制和面板是什么样子。大约二十分钟。

### 2. 写适配器

照 xpisode 仓库的 `docs/tutorials/device.md` 写。适配器放在你自己的新仓库里，比如 `xpisode-tron2`。

建议分两步：
- **先只做"读"：** 关节状态、相机。能录下来、能在面板上看到，再往下走；
- **再做"控制"：** 让 xpisode 能把动作发给机器人。

教程最后有一个协议检查，把它写进适配器仓库的测试。

### 3. 准备机器人电脑

照[准备一台机器人电脑](setup-robot-pc.md)做。那篇和 `host/doctor.sh` 是按 YAM 写的，新机型有几处不同：

- 第 4 步没有现成的模板。参考 `robots/_template/yam/`，自己写 `station.toml`、`LOG.md`；
- 没有 CAN 的话，`can.toml` 怎么处理，先和负责人商量；
- 体检里 `can-*`、`autosuspend`、`tuned` 这几项可能不适用，可以跳过。

照着做时发现哪里不对，就把这篇改对。

### 4. 写本体约定

在 `profiles/` 下写一份，可以参考 `profiles/yam-bimanual-3cam.md`。同一种机器人的所有电脑都遵守同一份约定，它们录的数据才能放进同一个数据集。

### 5. 提交

适配器仓库自己管。本仓库里，只改了 `robots/<站点>/` 时可以直接推送；改到共用的部分（脚本、模板、文档）要走 Pull Request。

### 6. 真机验收

照 [真机验收](acceptance.md) 做，要有人在场。全部通过才开始正式采集。

## 和大家一致的几条规矩

每条后面是为什么。不知道为什么的规矩容易被绕过，绕过了的代价往往要很久以后才显出来。

- **数据和别人的放在一起，不按机器人分文件夹。** 每条录制自己记着是哪台机器人、谁录的、什么任务、什么版本。按文件夹分，就多了一份会和录制里写的对不上的"真相"。
- **人名从共享名单里选，任务名先找有没有现成的。** 同一件事起了两个名字，数据就统计不到一起，也建不进同一个数据集。
- **做失败了也按"要"，录坏了才按"重录"。** 失败的尝试也是有用的数据。"重录"那条会在本机直接删掉、不上传，所以只给真正无效的录制用，比如摆放不对、中途被打断。已经上传的录制只有负责人能删，因为删了别人的数据集也会受影响。
- **xpisode 的版本全团队一样**，由本仓库决定。录制格式由 xpisode 决定，大家往同一个 OSS 里写，版本不同，别人就可能读不了你的数据。你的适配器版本你自己定。
- **机器人电脑上不改代码。** 在自己的电脑上改，推到 GitHub，再装上去。在机器上直接改，这台机器就和别的机器不一样了，录下来的数据也说不清是哪个版本录的。
- **每次在电脑上操作，都记进 `robots/<站点>/LOG.md`。** 下一个重装或排查这台机器的人，只能靠它知道之前发生过什么。

## 需要一起商量的

适配器怎么写，取决于你的机器人：
- **SDK 是什么形式**（C++、Python、ROS 2），控制要多实时。如果要求很高，可能要像 YAM 那样单独写一个实时控制程序；
- **用什么相机、装在哪里**。如果用 D405，可以直接用现成的 `xpisode-realsense`。

## 遥操作：先查清一件事

xpisode 对动作有一条硬要求：**示范时机器人收到的目标，要被录下来，而且和以后策略发出的目标是同一种。** 不然训练出来的模型，到了真机上动作的含义就对不上，而且很难查出来。

YAM 的做法是把遥操作写成 xpisode 的一个客户端，动作从 xpisode 发出去，自然就被录下了。机器人如果自带遥操作，不一定要放弃它，先查 SDK：

1. 用厂商遥操作时，适配器能不能读出厂商控制器收到的目标（关节目标或末端位姿），带时间、频率够用？
2. 策略上机时，能不能把同一种目标发给厂商控制器？

两条都能，就继续用厂商遥操作，适配器把遥操作目标当成一路数据录下来。少掉的是：人和策略之间的接管只能靠厂商切换，站点能记录，但不能裁决。

第 1 条做不到，就要自己写遥操作：输入设备（手柄、VR）写成一个适配器，再写一个遥操作客户端。这部分工作量最大，动手前先和负责人商量。

为什么这样要求，见 xpisode 的 `design/design.md` 5.1 节。

## 你会拿到的权限

| 仓库 | 内容 | 你的权限 |
| --- | --- | --- |
| `ningma-dev/xpisode` | xpisode 本身 | 只读。需要改的地方提 Issue |
| `ningma-dev/xpisode-site` | 团队的机器人配置和文档 | 可写。你的机器人目录由你审批，大家共用的部分由负责人审批 |
| `ningma-dev/xpisode-realsense` | D405 相机驱动 | 只读，装机时要用 |
| `ningma-dev/xpisode-i2rt` | YAM 手臂驱动 | 只读，装机时要用 |

另外还有团队共用的 OSS 上传钥匙，**只能上传和下载，不能删除**，只放在机器人电脑上。
