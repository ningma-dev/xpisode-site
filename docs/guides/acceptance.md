# 真机验收

在一台机器人上开始正式采集之前，逐项确认它在真机上工作正常。**有一项不通过，就不开始采集。**

**前提：** [准备一台机器人电脑](setup-robot-pc.md) 已经做完，两条跟随臂也[调过参](tune-arm.md)。

**要求：** 操作员在场，桌面清空。会启动站点、让手臂动。

先启动面板和站点：

```bash
cd ~/xpisode-site
scripts/serve.sh
scripts/run.sh --who <你的名字>
```

| 做什么 | 应该看到 |
| --- | --- |
| 不带名字启动站点（`scripts/run.sh`，不加 `--who`） | 拒绝启动 |
| 录制中拔掉一台相机 | 1 秒内停止录制，原因写明是哪台；播报一直持续到相机恢复 |
| 相机没接上时按录制键 | 不开始录制，面板和播报都说明原因 |
| 三台相机连续跑 10 分钟 | 面板的设备诊断里重置次数为 0，几乎没有丢帧 |
| 杀掉一条手臂的设备进程 | 控制权被收回，录制停止 |
| 手臂静止时杀掉站点进程 | 手臂停稳；重启后，没录完的那条标为"中断" |
| 按计划录 3 条：分别判"要"、"重录"、不判 | "重录"那条在本机被删掉、不上传；只有"要"的那条算完成 |
| 录完一条 | 1 秒内站点页显示快检结果 |
| 后台在生成代理视频时录制 | 控制节拍的抖动和不生成时一样 |
| 打开判断页 | 第一次打开不到 1 秒，切到下一条不到 0.5 秒 |
| 再起一个站点，去抢同一台相机 | 后启动的被拒绝，并说明相机被谁占用 |

每一项的结果都记进 `robots/<站点>/LOG.md`。全部通过以后，打开自动上传：

```bash
scripts/upload.sh
```

以上每项背后的机制，见 xpisode 仓库的 `docs/`。
