## 记日志

每在一台电脑上做一件事，就在 `robots/<站点>/LOG.md` 末尾加一条：

```markdown
## 2026-11-14 · 名字 · 准备一台机器人电脑，第 1–11 步
- 版本：本仓库 <git rev-parse --short HEAD 的输出>
- 结果：体检 0 FAIL，调参还没做
- 和文档不一样的地方：第 5 步……（已经改了文档）
```

## 写文档的规矩

1. 一篇只讲一件事，开头一句话说清做什么、什么时候用。
2. 通用：用 `<站点>` 这样的占位符，具体数值放在 `robots/<站点>/`。
3. 每一步写三样：为什么做（一句）、命令、成功是什么样子。
4. 说人话。术语能不用就不用；非用不可，第一次出现时用一句话解释。
5. 只讲部署。xpisode 本身的机制留给 xpisode 的文档，这里不重复。
6. 照着做时发现文档不对，就在同一次提交里把它改对。
