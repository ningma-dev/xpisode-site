# 本仓库是怎么组织的

只想照着操作的话，不用读这篇。想弄明白"为什么这么放"，或者要改本仓库的结构，再来读。

## 三样东西分开放

| 东西 | 放在哪 | 为什么 |
| --- | --- | --- |
| 代码 | GitHub 上的 `xpisode`、`xpisode-realsense`、`xpisode-i2rt` | 通用的东西，换个团队也能用 |
| 怎么部署 | 本仓库 | 只和我们团队有关：有哪些机器人、用哪个版本、怎么装 |
| 数据 | 每台机器的 `~/xpisode-data`，再上传到 OSS | 太大，也不该进仓库 |

开发在自己的电脑上做，机器人电脑上只装版本。这样任何一台机器坏了、重装了，都能从 GitHub 和 OSS 完整恢复。

## 一台机器人一个目录

```text
robots/<站点>/
  station.toml   这台机器人有哪些设备、怎么录（xpisode 叫它"站点文件"）
  machine.env    这台电脑的情况：主机名，相机和 CAN 插在哪个 USB 控制器上
  can.toml       每条手臂用的 CAN 适配器序列号
  tuned/         每条跟随臂的调参结果
  machine.md     装机时的硬件快照，以后拿来对比
  LOG.md         在这台机器上做过的每件事
```

- **只有一个 `main` 分支。** 每台机器都拉同一份，各自读自己的目录。改一次共用的脚本，所有机器都能用上，不用一台一台合并。
- **机器怎么知道自己是谁：** 装机时在仓库里写一个本地文件 `.station`，里面是站点名，这个文件不提交。不用主机名来认，是因为新装的系统主机名常常都一样。
- **目录名就是站点名**，每条录制都会记下它，所以定下来就不改。
- **文档里不写具体机器的数值**，数值都在这个目录里。所以同一份文档适用于所有机器。

## CAN 适配器为什么按序列号起名

每个 CAN 适配器都有一个出厂序列号。系统规则写的是"序列号是某某的那个，就叫 `can_follower_l`"。所以适配器插在哪个口、开机时先被认出来还是后被认出来，都不影响它的名字。

四个名字在每台 YAM 上都一样：`can_follower_l`、`can_follower_r`、`can_leader_l`、`can_leader_r`。所以各台 YAM 的站点文件几乎一样，只有序列号不同。

这条规则是 `host/can_rules.py` 根据 `can.toml` 自动生成的，不用手写。

## 后台任务为什么要避开某些 CPU 核

相机的数据通过 USB 进来，每个 USB 控制器由一个固定的 CPU 核负责处理。生成视频、上传数据这类后台任务，如果跑在同一个核上，相机就会丢帧。用低优先级也没用，这是旧站点上测出来的。

所以 `machine.env` 记下相机和 CAN 用的是哪几个核，脚本把后台任务放到其余的核上。设备换了插口，这些核可能就变了，`host/doctor.sh` 会检查出来。

## 版本怎么定

- `pyproject.toml` 写定三个代码仓库各用哪一次提交；
- `uv.lock` 写定其余所有依赖的版本；
- 手臂的实时控制程序和面板网页，不能直接随 Python 包装好，由 `scripts/build_pinned.sh` 按同一个版本编译。

所以"一个版本"就是本仓库的一次提交。

## 脚本和检查

能写成脚本的步骤都写成了脚本，每个脚本都可以重复运行。`host/doctor.sh` 只读，逐项检查机器有没有准备好，结果是 PASS、FAIL 或 TODO。文档里每一步的"成功的样子"，大多就是 doctor 的某一项变成 PASS。

| 脚本 | 做什么 | 会不会改系统 |
| --- | --- | --- |
| `host/setup.sh` | 系统设置 | 会，要 sudo |
| `host/can_rules.py` | 生成 CAN 命名规则 | 加 `--check` 只预览；不加要 sudo |
| `host/doctor.sh` | 体检 | 不会 |
| `host/snapshot.sh` | 打印硬件快照 | 不会 |
| `host/can_list.sh`、`host/xhci_list.sh` | 列出 CAN 和相机 | 不会，也不会打开设备 |
| `scripts/run.sh` | 启动站点（手臂会动） | 要有人在场 |
| `scripts/serve.sh`、`scripts/upload.sh` | 网页面板、自动上传 | 不会 |
| `scripts/oss.py` | 和 OSS 之间同步数据 | 会上传；删除只有负责人能做 |

## 在 Mac 上同时改几个仓库

把代码仓库克隆到本仓库旁边，然后运行 `scripts/dev_link.sh`。本仓库的环境就会直接用你改过的源码，不用先发版本。写定的版本不受影响，运行 `uv sync --locked` 就恢复原样。
