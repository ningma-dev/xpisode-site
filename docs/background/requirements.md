# xpisode 需求清单（穷举）

日期：2026-11-10。状态：草稿，待人工检查。

这份清单的用途是：在把设计固定下来之前，把所有需求一条条列出来，再看三个概念（读写图、独占、腰）能不能全部装下。`docs/design.md` 讲怎么做，这里只讲要什么。

## 0. 怎么穷举

先定坐标轴，再按坐标轴逐格去想。这样漏没漏，可以回头逐格检查。

| 轴 | 取值 |
| --- | --- |
| 谁 | 采集员、判断员、研究员、agent、管理员、方法作者、设备适配者、训练服务器、任务负责人、社区贡献者、未来的维护者 |
| 物的一生 | 物理布置 → 站点和设备 → 控制 → 采集 → 判断 → 数据集 → 导出和训练 → checkpoint → 评测 → 结果 → 共享 → 归档和删除 |
| 质量属性 | 正确、安全、可溯源、可复现、可比、快、能扩到大规模、不丢、隐私和合规、好维护、能演进、负担小、开放、成本可控、看得见 |
| 时间尺度 | 上线（11-16）、一年内（内部大规模使用）、开放给社区以后 |
| 会变的东西 | 机器人、传感器、方法、外部格式、人、组织、规模、法规、硬件状态、框架自己 |

每条需求标五项：

- **来源**：说＝你说过的；事＝发生过的事故或实测；定＝已有的决定；推＝我推断的。
- **归属**：图＝读写图；独占＝谁在动、谁在用；腰＝格式和协议里的含义；程序＝图上的一个外部程序；流程＝人和组织的事，不靠软件。
- **现状**：有、部分、缺。
- **期限**：上线、一年、社区、按条件（到了建造条件才做）。

### 16.4 三个概念装得下吗

共 151 条。把"归属"一列数一遍（一条可以有两个归属）：

| 归属 | 条数 | 说明 |
| --- | --- | --- |
| 图 | 57 | 最多。录制以后的一切几乎都在这里 |
| 流程 | 33 | 软件解决不了，要有人负责 |
| 腰 | 25 | 设备、时间、格式、接口 |
| 程序 | 20 | 都是图上的读者和写者，不需要核心有新概念 |
| 独占 | 17 | 见下面的发现 1 |
| 边 | 7 | 桥：对接外部的习惯 |

**没有一条需求需要第四个概念。** 但穷举之后，有四处发现，会改变设计：

**发现 1：独占出现在三个时间尺度上，其实是同一个概念。**

| 尺度 | 独占的是什么 | 今天叫什么 |
| --- | --- | --- |
| 约 100 毫秒 | 一个执行器 | 设备租约 |
| 秒到分钟 | 一组执行器 | 控制组的持有者 |
| 小时 | 整个站点（以及它的 GPU） | 负责方、预约（O2、CO5） |

design.md 里的"负责方"不是一个新概念，就是站点这一级的租约。预约是它的计划表，授权（O3）是一级租约把一部分权力转交给另一个名字。三级用同一套规则：有持有者，有期限，到期就收回；交接是一次记下来的事实。

**发现 2："当前"必须改成按取代来定（J2）。**

按时间最晚来定，在多台机器、时钟有偏差的情况下会出错。而七种记录的"当前"规则，都可以统一成"没有被任何人取代的那一条"。这要在冻结之前定。

**发现 3：最大的长期空白，正好是多本体最先会碰到的两处（D4、D11）。**

到目前为止，整个设计都默认两件事：一台主机，底座固定。逐际的机器人多半有自己的主控计算机，而且是会移动的。所以，设备协议的第二种传输（跨主机），以及随时间变化的坐标变换，是"一年"期限里最该先想清楚的。这两样都属于腰，一旦有人用就会被冻结，不能等到做的时候才临时决定。

**发现 4：删除是图白送的能力（I10）。**

只追加的图，最怕的就是"必须删"：隐私、误录、法规。但因为每一次写都记下了读了什么，反过来沿着"被谁读了"往前走，就能找出由一条录制派生出的全部东西：代理文件、导出、数据集、训练过的 checkpoint。删除本身也是一次写，记下删了什么、为什么删。现在什么都不用做，只要保证读记得全（L2、X2）。

### 16.5 需求之间的冲突，要取舍

| 冲突 | 我的倾向 |
| --- | --- |
| 无损原始数据 vs 存储和上传的成本 | 先实测编码再定；拿不准就先保留，因为保留下来的以后还能删 |
| 契约严格 vs 研究自由（有的研究就是想在缺一台相机时照样录） | 契约由清单和计划声明，研究者可以声明更少的必需流；但声明了的就要守 |
| 开放写判断 vs 垃圾数据 | 写的一边开放，信任在读的一边（J4） |
| agent 自动化 vs 安全 | agent 可以接入，不能让手臂动（S5） |
| 早冻结 vs 晚冻结 | 走完两道闸门再冻；D4、D11 的格式部分要在冻结前想好，哪怕先不实现 |
| 通用 vs 好管理 | 腰通用，边薄（design.md 第 8.3 节） |
