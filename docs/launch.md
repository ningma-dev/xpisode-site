## 3. 上线前要做的，按顺序

1. **你来定：**
   - 红外是否改用灰度 FFV1；
   - 推送用哪个远端；
   - 那三条相机时间戳可能偏了 11 秒的录制（07:51:34Z、07:51:46Z、07:51:59Z）怎么处理；
   - 谁有权删除已上传的录制，OSS 是否打开版本控制。
2. **回放站点端到端跑一次**，不碰硬件。
3. **停站点的时间窗（约 2–3 小时）：**
   1. 把 `dev` 合回正式检出：工作区、`repos/xpisode`、`repos/xpisode-realsense`、`repos/xpisode-i2rt`。
   2. 跑完整的 `scripts/check.sh`，包括会起站点进程的测试和 wheel 构建。
   3. 真机验收，结果记在 `deployments/` 下；有一项不过，就不开始正式采集：

   | 做什么 | 应该看到 |
   | --- | --- |
   | 不填名字就开始录制 | 被拒绝 |
   | 录制中拔掉一台相机 | 1 秒内中止，原因写明是哪台；播报持续到恢复 |
   | 相机不在时按录制键 | 不开始，面板和播报都说明原因 |
   | 运行中把系统时钟拨回 10 秒 | 相机不故障 |
   | 三台 D405 连跑 10 分钟 | `device.diagnostics` 里重置为 0，没有元数据的帧为 0 或很少 |
   | 杀掉一个机械臂的设备进程 | 控制组收回，录制中止 |
   | 手臂静止时杀掉站点进程 | 设备停稳；重启后未完成的录制恢复为 `interrupted`，运行记录补上 |
   | 换一个机器人模型后开始录制 | 不会因录制器忙而被中止 |
   | 按计划录 3 行：要、重录、不判 | 重录那条在本机被删、不上传；只有判为要的那一行算完成 |
   | 录完一条 | 1 秒内站点页出规则快检的结果 |
   | 录制时后台在生成代理视频 | 控制节拍的抖动和不生成时一样 |
   | 判断页 | 第一次打开 p95 < 1 秒，切到下一条 p95 < 0.5 秒 |
   | 起第二个站点去抢同一台相机 | 后启动的被拒绝，并说明被谁占用 |
   | 删掉 `local/` 重启面板 | 索引和代理重建，结果一致 |

4. **真的 OSS 上实测四项**（用你的凭证）：按文件清单下载、按前缀列出、只能新增的凭证删不掉东西、完整列出一遍要多久。然后第一次推送。
5. **打版本号、推送**：所有仓库一次推到私有远端；RealSense 依赖的框架版本改成推送的那个提交，工作区的 `uv.lock` 随之更新。
6. **第二台机器照着文档装一遍**（有的话）。
